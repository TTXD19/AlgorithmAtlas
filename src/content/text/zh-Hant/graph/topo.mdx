有向圖的**拓撲順序**是把所有節點排成一列，讓每一條邊 `u → v` 的 `u` 都排在 `v` 前面。它存在的條件恰好是圖為 **DAG**（有向無環圖），而且通常不只一種。**Kahn 演算法**的直覺是「誰不用等，誰先做」：**入度**為 0 的節點沒有任何前置條件，可以排第一；排出去之後刪掉它的出邊，某些節點的入度降到 0，換它們上場。**DFS 法**從另一頭想：一個節點要等它能走到的節點全部處理完才算**完成**，把完成順序反轉，就是拓撲順序。

為什麼對：Kahn 只在 `indeg[v]` 降到 0 時把 `v` 放進佇列，這時每條指向它的邊 `u → v` 都已被刪掉，也就是 `u` 都已輸出，所以每條邊都被遵守。它在 DAG 上不會卡住：非空的 DAG 一定有入度 0 的節點，否則沿著入邊一直往回走，節點有限，終究會走回走過的點，形成環；刪掉節點後剩下的仍是 DAG。反過來，佇列空了卻還有節點沒輸出，剩下的每個節點入度都 ≥ 1，往回走必定繞圈，所以**輸出數少於 V 就代表有環**，這是 Kahn 附帶的環偵測。DFS 法看任一條邊 `u → v`：檢查它時 `v` 若是白色，會在 `u` 之前遞迴完成；若是黑色，早就完成了；若是灰色（還在呼叫堆疊上），那就是環。所以無環時 `v` 一定比 `u` 先完成，反轉後 `u` 就在 `v` 前面。

複雜度：Kahn 建入度表掃一次所有邊 O(E)；每個節點進出佇列各一次 O(V)；每條邊只在它的起點被取出時減一次入度 O(E)，合計 **O(V+E)**。DFS 法每個節點進入一次、每條邊檢查一次，也是 **O(V+E)**。兩者沒有最好或最壞情況之分，整張圖一定要跑完。額外空間是入度表、佇列、顏色陣列與輸出，都是 **O(V)**（鄰接串列本身的 O(V+E) 算在輸入裡）。DFS 的遞迴深度最壞是 V（一條長鏈），Python 預設遞迴上限只有 1000，節點多時改用 Kahn。

最常見的錯是**邊的方向接反**：LeetCode 207、210 的 `[a, b]` 表示「修 a 之前要先修 b」，邊是 `b → a`。DFS 法常忘了**反轉**完成順序，或只用一個 visited 布林值、不區分灰色，結果圖裡有環也照樣輸出一個錯的順序；外層迴圈也要對每個節點都試，因為圖不一定連通。和相鄰課程的關係：Kahn 的佇列走法就是 BFS 的骨架，DFS 法是 DFS 的後序，三色標記和 Cycle Detection 完全相同，拓撲排序等於「做環偵測時順便記下順序」。要字典序最小的順序，把佇列換成最小堆積，時間變成 `O(V log V + E)`；要知道最少分幾輪平行做完，就讓 Kahn 一次處理一整層。有了拓撲順序，照順序鬆弛每條邊就能在 DAG 上求最短路徑，那是 DAG Shortest Path 的做法。
