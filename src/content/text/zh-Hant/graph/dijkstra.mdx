BFS 能在無權圖上找最短路徑，是因為佇列的先進先出剛好等於「距離由小到大」。邊一旦有權重，這個對應就斷了：走兩段短路可能比走一段長路更近。**Dijkstra** 把佇列換成**最小堆積**，為每個節點維護目前已知的最短距離 `dist`（一開始是 ∞）。每一輪取出「還沒確定、而且 `dist` 最小」的節點 `u`，宣告它的距離確定，再用它的每條邊做**鬆弛**：若 `dist[u] + w < dist[v]`，就把 `dist[v]` 改小，並記下 `parent[v] = u`。節點被確定的順序，就是它們離起點由近到遠的順序。

為什麼取出的當下就能確定？設 `u` 是未確定節點裡 `dist` 最小的，值為 d。任何一條從起點到 `u` 的路徑，都得在某處第一次踏出「已確定集合」，走到某個未確定的節點 `y`。`y` 的前一個節點已經確定、確定時也用這條邊鬆弛過 `y`，所以走到 `y` 的長度至少是 `dist[y]`，而 `dist[y] ≥ d`；剩下從 `y` 到 `u` 的邊權都**非負**，只會讓總長再變大。因此沒有路徑比 d 更短，這就是這個貪婪選擇正確的原因。證明裡用到了「邊權非負」，負權邊會直接打破它：`A→B = 2`、`A→C = 3`、`C→B = −2`，B 在第二輪就以 2 被確定，但 `A→C→B` 只要 1。

每個節點只會被確定一次，確定時掃過它的邊，所以每條邊最多鬆弛一次（無向圖兩個方向各一次）。每次鬆弛成功就 push 一筆，堆積最多 O(E) 筆，每次 push／pop 是 O(log E)，而 E ≤ V² 使得 log E ≤ 2 log V，總時間 **O((V + E) log V)**。空間上 `dist` 與 `parent` 是 O(V)；這裡用的是**延遲刪除**寫法，被更新掉的舊紀錄留在堆積裡，最壞累積到 O(E) 筆，換成支援 decrease-key 的堆積才能壓回 O(V)。不用堆積、每輪線性掃描找最小值則是 **O(V²)**，在 E 接近 V² 的稠密圖上反而比堆積版的 O(V² log V) 快。只問單一終點時，終點被**取出**的那一刻就能結束，實務上常常只看了圖的一小部分，但最壞情況仍要走完整張圖。

常見錯誤有三個。第一，沿用 BFS 的習慣在 **push 時**就標記已走訪：Dijkstra 的節點可能先被遠路發現、之後才被近路更新，只能在**取出時**確定。第二，忘了跳過舊紀錄 `if d > dist[u]: continue`：答案不會錯，但同一個節點會被重複展開，稠密圖上會慢很多。第三，C++ 把距離存在 `int`，權重一累加就溢位。怎麼和鄰近的演算法分工：邊權全是 1 用 **BFS**；權重只有 0 和 1 時，用雙端佇列的 0-1 BFS 就有 O(V + E)；有負權邊用 **Bellman-Ford**；圖是 DAG 時先拓撲排序再依序鬆弛，O(V + E) 而且負權也行；要任兩點之間的距離、而且圖不大，用 **Floyd-Warshall**。Prim 的最小生成樹和 Dijkstra 長得幾乎一樣，差別只在堆積裡比的是「單一條邊的權重」，而不是「從起點累加的距離」。
