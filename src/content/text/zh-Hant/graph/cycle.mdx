環就是從某個節點出發沿著邊走，最後又回到它。DFS 很適合找環，因為**呼叫堆疊就是從起點走到目前節點的那條路徑**。有向圖用**三色標記**：**白色**還沒拜訪，**灰色**已經進入但還沒離開（在堆疊上），**黑色**出邊全部查完。在 `u` 看到邊 `u → v` 時，若 `v` 是灰色，`v` 就在目前的路徑上，沿路徑從 `v` 走到 `u` 再走 `u → v` 就繞回來了，這條邊叫**回邊**（back edge）。只用一個 `visited` 不夠：在 `A → B → D`、`A → C → D` 這種菱形裡，D 第二次被碰到時已經拜訪過，但圖裡沒有環。黑色和灰色的區別就是用來排除這種誤判。

為什麼「有環」等價於「DFS 會碰到灰色節點」。碰到灰色的 `v` 時，堆疊上從 `v` 到 `u` 每一步都是真的邊，加上 `u → v` 就是一個環，所以不會誤報。反過來，假設圖裡有環，令 `v` 是環上**第一個**被拜訪的節點：那一刻環上其他節點都是白色，而且沿著環走得到，所以它們都會在 `dfs(v)` 返回之前被拜訪；其中 `v` 在環上的前一個節點 `u` 檢查 `u → v` 時，`v` 還在堆疊上，一定是灰色，所以不會漏報。這個論證也說明碰到黑色節點可以直接略過：任何環都會在它的第一個節點還是灰色時被抓到。

無向圖不能照搬：每條邊都是雙向的，從 `u` 走到 `v` 之後，`v` 馬上會看到來時的 `u`。**DFS 版**要略過「剛走過來的那條邊」，其餘已拜訪的鄰居都代表環；排除時要比對**邊的編號**而不是父節點，否則兩條平行邊 `u – v` 構成的環會被漏掉。**併查集版**逐條加邊，兩端 `find` 相同表示之間早有一條路，這條邊一加就閉合成環；它只需要邊的清單，適合邊一條條到來的情境。但併查集**不能用在有向圖**：`A → B`、`A → C`、`B → C` 加到第三條時 B、C 已經同群，這張圖卻沒有有向環。無向圖還有一個計數檢查：森林的邊數恰好是 `V − 連通分量數`，邊數比這個多就一定有環。

複雜度：三色 DFS 裡每個節點白變灰、灰變黑各一次，每條有向邊檢查一次，時間 **O(V+E)**；顏色陣列 O(V)，遞迴深度最壞 O(V)（一條長鏈），空間 **O(V)**，不算輸入的鄰接串列。無向 DFS 每條邊從兩端各看一次，仍是 O(V+E)。併查集版搭配路徑壓縮與按大小合併是 `O(V + E·α(V))`，實務上就是線性。只問有沒有環時，找到第一個就能停。常見的錯有三個：只從節點 0 開始 DFS，漏掉不連通的部分；Python 遞迴上限預設 1000，節點多時要改成迭代，或改用 Topological Sort 的 Kahn 入度法，排完的節點少於 V 就有環；每個節點**只有一條出邊**時（鏈結串列、`x → f(x)` 的序列），用 Fast & Slow Pointers 就能以 O(1) 空間找環。
