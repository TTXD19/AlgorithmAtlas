算 xⁿ 最直接是乘 n − 1 次。**快速冪**用分治把指數切半：`xⁿ = (x^⌊n/2⌋)²`，n 是奇數時再多乘一個 x。算出一半、平方一次就得到全部，遞迴式是 `T(n) = T(n/2) + O(1)`，套 Master Theorem 的 a = 1、b = 2、d = 0 落在情況 2，是 **O(log n)** 次乘法。最常見的錯是把 `power(x, n/2)` 呼叫兩次再相乘：遞迴式變成 `T(n) = 2T(n/2) + O(1)`，又回到 O(n)，關鍵在「一半只算一次」。

迭代版從二進位看同一件事。把 n 寫成 `Σ bᵢ·2ⁱ`，就有 `xⁿ = ∏ x^(2ⁱ)`，只乘 bᵢ = 1 的那幾項。從最低位往最高位掃，維持兩個**不變量**：處理第 i 位之前，`base = x^(2ⁱ)`，`result = x^(n 的低 i 位)`。第 i 位是 1 就把 base 乘進 result，然後 base 平方變成 `x^(2ⁱ⁺¹)`、n 右移一位。所有位元處理完，低位就是整個 n，result 正是 xⁿ。這個寫法不用遞迴，額外空間 O(1)。

複雜度：n 有 `⌊log₂ n⌋ + 1` 個位元，每一位最多一次平方加一次乘法，總共不超過 **2 log₂ n** 次乘法；指數變成十倍，位元只多 3、4 個。這裡的 O(log n) 是「乘法的次數」：取模運算的每次乘法是 O(1)；沒有取模的大整數，數字越乘越長，每次乘法本身就越來越貴。空間上迭代版 O(1)，遞迴版要 O(log n) 的呼叫堆疊。快速冪只用到**結合律**和一個「1」（單位元素），所以不只適用於數字：矩陣的「1」是單位矩陣，一次 k×k 矩陣乘法 O(k³)，整體 O(k³ log n)，這就是用矩陣快速冪算線性遞推第 n 項的做法；置換、仿射變換等可以合成的操作也都能這樣「倍增」。

常見的坑：**溢位**，每做一次乘法就要取模，而且兩個小於 mod 的數相乘必須放得進型別，mod = 10⁹+7 時 64 位元整數夠用，mod 接近 10¹⁸ 時就要 128 位元或特別的乘法；**負指數**（LeetCode 50）要先取倒數，而 32 位元的 `INT_MIN` 直接取負會溢位，先轉成 64 位元；`x⁰ = 1` 包括 x = 0 的情況，而 mod = 1 時答案應該是 0，所以初值寫 `1 % mod`。和相鄰課程的關係：Master Theorem 那篇的二分搜尋和這裡是同一個遞迴式；數學主題的 Modular Arithmetic 會用快速冪算模反元素，也就是費馬小定理的 `a^(p−2) mod p`。
