暴力比對在 `T[i]` 和 `P[j]` 失配時，會把 P 往右移一格、把 i 退回去重新比。浪費在於：失配之前已經確認 `T[i−j..i−1] = P[0..j−1]`，這段文字的內容其實完全由 P 決定，根本不必再看一次 T。所以「失配後 P 可以往右滑多遠而不漏掉答案」只和 P 本身有關，可以事先算好。這就是 **KMP**（Knuth–Morris–Pratt）的出發點。

設已經對上 j 個字元。P 往右滑之後若還可能成功，滑過去的 P 開頭必須等於已對上那段 `P[0..j−1]` 的結尾，也就是 `P[0..j−1]` 的一個**邊界**：既是真前綴、又是後綴的字串。滑動量越小，需要的邊界越長，所以保留**最長的邊界**就是最小的可行滑動量，比它更小的滑動量需要更長的邊界，而那不存在，中間跳過的位置一定不是答案。定義**前綴函數** `pi[i]` 是 `P[0..i]` 最長邊界的長度，失配時令 `j = pi[j−1]`，i 不動，繼續拿 `T[i]` 和新的 `P[j]` 比，還是不合就再退，直到對上或 j = 0。例如 P = aabaaab 已經對上 aabaa，它的最長邊界是 aa，就直接滑到只保留 aa 對齊的位置。

建 pi 表用的是同一套規則，只是拿 P 和自己比：j 是目前的邊界長度，`P[i] = P[j]` 時邊界延長一格，否則退到 `pi[j−1]` 再試。複雜度要用**均攤分析**：每處理一個字元 j 最多加 1，每次後退 j 至少減 1，而 j 不會小於 0，所以後退的總次數不會超過前進的總次數。建表 O(m)、搜尋 O(n)，合計 **O(n + m)**，而且是最壞情況的保證；額外空間只有 pi 表，**O(m)**。另一種常見寫法是對「P、#、T」接起來的整串求 pi，值等於 m 的位置就是一次出現。

常見的坑：`pi[0]` 一定是 0，建表的 i 要從 1 開始，否則整段會被當成自己的邊界；失配時查的是 `pi[j−1]` 而不是 `pi[j]`；後退要用 while 而不是 if，可能要連退好幾次；找到一次之後 j 要設成 `pi[m−1]` 而不是 0，否則在 aaaaa 裡找 aaa 會漏掉重疊的出現。pi 表本身也很有用：字串的最短週期是 `m − pi[m−1]`，它能整除 m 時，字串就是由這段重複組成。和鄰近課程的關係：Rabin-Karp 用雜湊做到期望線性，KMP 則是確定性的；下一篇 Z-Algorithm 從另一個角度記錄「每個位置和開頭的共同前綴」，能解的問題幾乎相同；有很多模式時，把 pi 的想法搬到字典樹上就是 Aho–Corasick。
