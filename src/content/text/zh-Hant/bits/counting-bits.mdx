「一個整數裡有幾個位元是 1」叫做 **population count**（popcount，也叫 Hamming weight）。最直接的做法是**逐位檢查**：看最低位 `n & 1` 加進計數，再 `n >>= 1`，直到 n 變 0。迴圈次數等於位元長度，和裡面有幾個 1 無關。**Brian Kernighan** 的做法只在有 1 的地方停：每次執行 `n &= n - 1` 恰好清掉最低位的那個 1，清幾次 n 才變 0，就有幾個 1。

為什麼 `n & (n - 1)` 只清掉最低位的 1：設 n 最低位的 1 在第 j 位，那麼第 0 到 j − 1 位全是 0。減 1 需要借位，第 j 位變 0、第 0 到 j − 1 位全變 1，第 j 位以上完全不變。再和原本的 n 做 AND：第 j 位是 1 & 0 = 0，更低的位是 0 & 1 = 0，更高的位是 x & x = x，結果正好是「n 拿掉最低位的 1」。迴圈維持的不變量是 `count + popcount(n)` 恆等於原數的 1 的個數：每輪 count 加 1、n 少一個 1，n 變 0 時 count 就是答案。同一個式子還能判斷 **2 的冪次**：n > 0 且 `n & (n - 1) == 0`，代表 n 只有一個 1。

設 1 的個數是 k、位元寬度是 w。Kernighan 是 **O(k)**，逐位檢查是 O(位元長度)，最壞都是 O(w)（32 個位元全是 1 時兩者一樣），但 1 越稀疏 Kernighan 越省；兩者都只用 **O(1)** 空間。要算 0 到 n 每個數的 1 個數（LeetCode 338），每個數各跑一次 Kernighan 總共 O(n log n)；改用遞推 `bits[i] = bits[i & (i - 1)] + 1`：`i & (i - 1)` 比 i 小、恰好少一個 1，而且早就填好了，所以整張表 **O(n)**，除了答案陣列本身不需要額外空間（`bits[i >> 1] + (i & 1)` 也是一樣的效果）。**漢明距離**是 `popcount(a ^ b)`；要算整個陣列所有數對的漢明距離總和，不必 O(n²) 兩兩比，改成逐位看：某一位上有 c 個 1、n − c 個 0，這一位就貢獻 c × (n − c)，總共 O(32n)。

最常見的坑是**負數**。Python 的整數沒有固定寬度，−1 可以想成有無限多個 1，`n &= n - 1` 只會得到 −2、−4、−8⋯⋯永遠到不了 0，逐位檢查的 `n >>= 1` 也會卡在 −1；要先 `n &= 0xFFFFFFFF` 轉成 32 位元。C++ 要用 `std::uint32_t`，有號負數右移通常補 1，一樣停不下來。實務上直接用內建：Python 3.10 起的 `int.bit_count()`、C++ 的 `std::bitset<32>(n).count()`、GCC/Clang 的 `__builtin_popcount`、C++20 的 `std::popcount`，通常會編譯成 CPU 的 POPCNT 指令。自己會寫 Kernighan 的價值在「清掉最低位的 1」這個動作：Subset Enumeration 的 `(sub - 1) & mask` 是同一種借位，XOR Tricks 用來分組的 `diff & -diff`、Fenwick Tree 的 `i & -i` 是它的姊妹式（取出最低位的 1 而不是清掉），Bitmask DP 裡 popcount(mask) 就是子集大小。
