**選擇排序**把陣列分成兩區：左邊是**已排好**的區域，右邊是**未排序**的區域。每一輪把未排序區從頭掃到尾，記住最小值在哪個索引，掃完再把它和未排序區的第一格交換，已排好的區域就長一格。n−1 輪之後前 n−1 格都定位了，剩下的最後一格一定是最大的，不用再處理。

正確性靠一個不變量：第 i 輪（從 0 算起）結束後，`a[0..i]` 是整個陣列最小的 i+1 個元素，而且由小到大排好。這一輪開始時，未排序區的每個元素都不小於已排好區的任何元素；挑出其中的最小值放到 `a[i]`，既不破壞順序，也保證它是剩下元素裡最小的，歸納下去就成立。和氣泡排序靠相鄰交換一步步把最大值推到尾端不同，選擇排序只記索引，確定之後**一次交換**就讓元素直接到達最終位置，所以交換最多 n−1 次。再進一步：把每一格連到「這格的元素排好後該去的位置」會形成若干個環，每次交換剛好從一個環拆出一個定位的元素，所以元素互不相同時，交換次數正好是 `n − 環數`，也就是只用交換排好序的最少次數。

複雜度：第 i 輪要比較 n−1−i 次，總共 `(n−1) + (n−2) + … + 1 = n(n−1)/2`。這個數字**和輸入無關**：不看完未排序區的每一格，就無法確定誰最小，沒有提前結束的機會。所以最好、平均、最壞都是 **Θ(n²)** 次比較，已經排好的陣列也要比 n(n−1)/2 次，只是交換 0 次。交換最多 n−1 次，寫入是 O(n)；只多用一個索引變數，額外空間 **O(1)**。

最常被忽略的是它**不穩定**：交換會把 `a[i]` 一口氣丟到後面，可能越過和它同值的元素。例如依分數排序 `[(3, A), (3, B), (1, C)]`，第一輪把 (3, A) 和 (1, C) 交換，得到 `[(1, C), (3, B), (3, A)]`，A、B 的順序反了。要穩定得改成取出最小值、中間元素右移一格再放回，但寫入次數會變成 O(n²)，最大的優點也沒了。另一個常見錯誤是在內層迴圈一看到更小的就交換，交換次數會退化成 O(n²)；內層只該更新索引。和鄰居比較：氣泡排序的交換次數等於逆序對數量，但穩定、能提前結束；插入排序在近乎有序時是 O(n)，小陣列實務上都選它；**堆積排序**則是選擇排序的升級版，把「掃一遍找最值」換成堆積的 O(log n)，整體變成 O(n log n)。
