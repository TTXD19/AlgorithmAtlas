**子序列**是從序列裡刪掉任意幾個元素、剩下的保持原本順序，不必連續；**最長共同子序列（LCS）**就是同時是 A 和 B 子序列的最長那一個。暴力法列出 A 的 2ᵐ 個子序列逐一檢查，完全不可行。DP 的狀態定義成兩個**前綴**：`dp[i][j]` 是「A 的前 i 個」和「B 的前 j 個」的 LCS 長度，表大小 `(m+1) × (n+1)`，第 0 列和第 0 行代表空序列，全是 0，答案在右下角 `dp[m][n]`。

轉移只看兩個前綴的**最後一個元素**。若 `A[i−1] = B[j−1]`，一定存在一個最長的 LCS 以它結尾：就算某個 LCS 沒用到這對字，把它最後一個字換成這對字仍然合法、長度不變，所以 `dp[i][j] = dp[i−1][j−1] + 1`。若兩者不同，它們不可能同時是 LCS 的最後一個字，至少有一個沒被用到：沒用到 A 的就是 `dp[i−1][j]`，沒用到 B 的就是 `dp[i][j−1]`，取較大者。每一格只依賴上方、左方、左上方，**逐列由左到右**填就保證用到的格子都已算好。

複雜度是 m×n 格、每格 O(1)，**O(mn)** 時間。空間：要還原 LCS 本身就得留著整張表，**O(mn)**，從右下角開始，相同就收下這個字往左上走，不同就往較大的那一邊走；只要長度的話，每一列只用到上一列，滾動兩列降到 **O(min(m, n))**。兩段一萬字的文字是一億格，時間還可以，但整張表要好幾百 MB，這時要改用 Hirschberg 的分治法在線性空間裡還原答案。

常見的坑：**子序列**和**子字串**分不清，「最長共同子字串」要求連續，轉移變成相同時 `dp[i−1][j−1] + 1`、不同時歸零，答案是整張表的最大值而不是右下角；索引差一，`dp` 的第 i 列對應的是 `A[i−1]`；以為 LCS 唯一，平手時往上或往左會得到不同但一樣長的答案。和鄰近課程的關係：只允許刪除與插入時，把 A 變成 B 的最少步數是 `m + n − 2·LCS`，再加上「取代」就是下一篇的 Edit Distance，填表方式完全一樣；LIS 那篇提過，當其中一個序列元素互不重複時，LCS 可以轉成 LIS，用 O(n log n) 解決。
