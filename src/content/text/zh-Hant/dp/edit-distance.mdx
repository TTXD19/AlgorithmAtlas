**編輯距離**（Levenshtein 距離）是把字串 A 變成 B 所需的最少操作次數，允許三種操作：**插入**一個字、**刪除**一個字、把一個字**取代**成另一個字。狀態和 LCS 一樣看兩個前綴：`dp[i][j]` 是「A 的前 i 個字變成 B 的前 j 個字」的最少步數。邊界很直觀：`dp[i][0] = i`（刪光），`dp[0][j] = j`（全部插入），答案在 `dp[m][n]`。

轉移同樣只看最後一個字。若 `A[i−1] = B[j−1]`，這兩個字直接對上，`dp[i][j] = dp[i−1][j−1]`，不用花任何一步。若不同，在任何一組最佳操作裡，A 的最後一個字只有三種下場：被**取代**成 B 的最後一個字（左上 `dp[i−1][j−1]` + 1）、被**刪除**（上方 `dp[i−1][j]` + 1），或者它留著、B 的最後一個字是**插入**的（左方 `dp[i][j−1]` + 1）。三種情況涵蓋了所有可能，取最小值就是答案。填表順序和 LCS 一樣逐列由左到右。

複雜度 **O(mn)** 時間；要還原操作序列需要整張表 **O(mn)**，從右下角看每一格是由哪一項算出來的往回走即可。只要距離時，每一列只依賴上一列，但轉移用到「左上角」，覆寫前要先用一個變數存起來，空間降到 **O(min(m, n))**。實務上常只關心「距離是否 ≤ k」，例如拼字建議只看 1、2 步內的字：距離 ≤ k 的路徑一定待在 `|i − j| ≤ k` 的斜帶裡，只算這條帶子就是 **O(k·n)**，長度差超過 k 更可以直接跳過。

常見的坑：字相同時還加 1；邊界的第 0 列、第 0 行忘了初始化成 0..n、0..m；把「兩個相鄰字對調」當成一步，Levenshtein 距離裡 teh → the 其實要兩次取代，想算一步要改用多了「交換」操作的 Damerau 距離。三種操作的成本不一定要相同，OCR 或語音辨識常把某些取代設得比較便宜，轉移式照樣成立，只是把 +1 換成各自的成本。和上一篇的關係：拿掉「取代」、只准插入與刪除，答案就變成 `m + n − 2·LCS`；同樣「兩個前綴」的表格也出現在 Interleaving String、Distinct Subsequences 和萬用字元比對。
