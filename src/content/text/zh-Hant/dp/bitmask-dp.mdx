有些問題的後續決策取決於「**哪些東西已經用過**」，而不只是用了幾個：TSP 要知道哪些城市去過，指派問題要知道哪些工作被挑走了。這個「集合」本身就是狀態。元素少的時候，把集合編碼成一個 n 位元整數 `mask`，第 i 位是 1 代表第 i 個元素在集合裡，2ⁿ 個集合就對應到 0 到 2ⁿ − 1 的整數，可以直接當陣列索引，這就是 **Bitmask DP**。加入元素是 `mask | (1 << i)`，檢查是 `mask >> i & 1`，全都是 O(1) 的位元運算（Subset Enumeration 那篇的工具）。

以 TSP 為例，`dp[mask][j]` 是「從 0 出發、恰好走過 mask 裡的城市、最後停在 j」的最小成本。為什麼一定要記 j：之後還要走多遠，取決於現在人在哪裡，只記 mask 不夠。但只要 mask 和 j 相同，前面怎麼走到這裡都不影響後面，所以兩條到達同一狀態的路徑只需要留比較短的那條，這就是最佳子結構。轉移是 `dp[mask | (1 << k)][k] = min(dp[mask][j] + d[j][k])`，k 是還沒去過的城市；全部走完後再加上回到 0 的距離取最小。填表順序：加入元素只會讓整數變大，所以 **mask 由小到大**掃一遍就保證用到的狀態都已算好。

複雜度：TSP 有 2ⁿ·n 個狀態、每個試 n 個下一站，**O(2ⁿ·n²)** 時間、**O(2ⁿ·n)** 空間。n = 16 時約 1.7×10⁷ 次運算，n = 20 時約 4.2×10⁸ 次、表格要 2²⁰×20 個整數（80 MB），差不多是極限。指派問題因為「下一個是第幾個人」可以從 mask 裡 1 的個數算出來，狀態只要 mask，**O(2ⁿ·n)**。對照暴力：n = 20 時排列有 20! ≈ 2.4×10¹⁸ 種，所以 Bitmask DP 把「階乘」降成「指數乘多項式」，但仍是指數時間，TSP 本身是 NP-hard，n 再大就只能用近似或啟發式方法。

常見的坑：C++ 的比較運算子比 `&` 先算，`mask & 1 << j == 0` 其實是 `mask & ((1 << j) == 0)`，位元運算一律加括號；起點限制沒有處理，TSP 不從 0 出發會算出多餘的狀態甚至錯的答案；INF 相加溢位；n 超過 20 還硬開 2ⁿ 的表，記憶體先爆。狀態可以用「推出去」（從 dp[mask] 更新更大的 mask）或「拉進來」（dp[mask] 由拿掉一個元素的子集合算出）兩種方向寫，兩者等價。當轉移需要「把 mask 拆成兩個子集合」時，就要列舉子集合，對所有 mask 加總是 3ⁿ；Shortest Path Visiting All Nodes 則是在 (mask, 節點) 的狀態圖上做 BFS，同一個狀態設計、換成圖論的解法。
