樹沒有環，把某個節點當成根之後，每個節點底下的**子樹彼此獨立**，這正是 DP 需要的重疊子問題與最佳子結構。**樹上 DP** 替每個節點 u 定義 `dp[u]`，代表「只看 u 的子樹」時的答案，並且只用子節點的 dp 值算出來。計算順序因此必須是**後序**：先把所有子節點算完，再處理自己，這和 Traversal 那篇的後序走訪完全一樣，只是回傳值換成問題要的量。

以**樹的直徑**為例，要分清兩個量。`down[u]` 是從 u 往下的最長鏈，會回傳給父節點，因為父節點只能把一條直鏈接上去；`through[u] = 左鏈 + 右鏈` 是「在 u 轉彎」的最長路徑，只拿來更新全域答案，**不回傳**。正確性來自一個觀察：樹上任何一條路徑都有唯一的最高節點，路徑在那裡由兩條往下的鏈組成，所以對每個節點都算一次 through，取最大值就不會漏掉任何路徑。直徑不一定經過根，這就是為什麼每個節點都要嘗試更新答案。

當每個節點有「選或不選」這類決策時，每個節點存**多個狀態**。最大權獨立集記 `take[u]` 和 `skip[u]`：選 u 時子節點都不能選，`take[u] = w[u] + Σ skip[v]`；不選 u 時子節點自由，`skip[u] = Σ max(take[v], skip[v])`。每條邊只在它的子節點算完時被用到一次，總時間 **O(n)**；空間除了 dp 陣列，遞迴深度是樹高 **O(h)**，退化成一條鏈時就是 O(n)。要「每個節點當根」的答案時，用**換根**：第一趟由下往上算出以某個根的結果，第二趟由上往下，把父節點的答案用 O(1) 轉移給子節點，整體仍是 O(n)，而不是做 n 次 O(n)。

常見的坑：把 through（轉彎的路徑）回傳給父節點，得到的「路徑」其實分岔了；節點值有負數時（Binary Tree Maximum Path Sum）要允許不接子樹的鏈，也就是和 0 取最大；一般樹用鄰接串列存時，遞迴要記住父節點，不然會沿著無向邊走回去；Python 對 10 萬個節點的鏈狀樹遞迴會超過預設上限 1000，改用迭代排出父在前的順序、再反向處理。和其他課程的關係：Binary Tree Basics 的「樹高」就是最簡單的樹上 DP；House Robber 那種一維的「相鄰不能同時選」搬到樹上，就是最大權獨立集；監視器覆蓋（Binary Tree Cameras）則需要三個狀態。
